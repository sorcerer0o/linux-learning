Day01 Linux 知识点日报

1. 32 位操作系统最多给一个进程分配 2^32（4GB）虚拟地址空间，分为用户态空间（用户程序可访问）和内核态空间（只能内核访问，用户程序要通过系统调用进入）
2. 程序运行起来就是进程；进程是资源分配的基本单位；进程间是隔离的，不能直接访问对方内存
3. 进程切换开销大（要切换地址空间、保存恢复上下文、刷缓存）
4. 线程是轻量级的进程；一个进程至少包含一个线程，就是 main 所在的主线程
5. 线程是程序调度的基本单位，CPU 调度的是线程
6. 同一进程内多个线程共享资源：全局/静态变量、堆内存、文件描述符、代码段、信号处理函数
7. 为了区分不同线程，每个线程都有自己的独立栈空间（存局部变量和调用信息）
8. 线程切换开销比进程小很多（不需要切换地址空间）
9. pthread_create(thread, attr, start_routine, arg) 四个参数：thread 传出参数保存线程 ID（pthread_t 是线程 ID 的类型）；attr 线程属性默认 NULL；start_routine 是函数指针，指向线程入口函数，线程所有操作都从这个函数开始；arg 传给入口函数的参数，不需要可传 NULL
10. 编译 pthread 程序要加 -lpthread 链接选项
11. 指针家族复习：指针数组是元素为指针的数组；数组指针是指向数组的指针；函数指针是指向函数的指针；指针函数是返回值为指针的函数
12. 信号是一种异步的事件通知机制，也是一种进程间通信机制
13. 中断针对的对象是 CPU，产生后立刻执行；信号针对的对象是进程，产生后可能有延迟，可能暂存在进程的未决信号集里
14. 硬件中断是硬件设备通知 CPU 处理事件；软件中断是软件程序通知 CPU 处理事件（如系统调用）
15. 用 kill -l 可以查看所有信号：1-31 是标准信号，不排队，用位图存储；34-64 是实时信号，排队，用位图和链表存储
16. 信号执行类型：term 终止进程；stop 暂停进程；cont 继续进程；ign 忽略信号
17. 常见信号：SIGINT（2，Ctrl+C，终止）；SIGQUIT（3，Ctrl+\，终止并产生 core dump）；SIGKILL（9，立即终止，不可捕获不可忽略）；SIGTERM（15，可捕获，用于优雅退出）；SIGSTOP（19，停止，不可捕获不可忽略）；SIGCONT（18，继续）；SIGCHLD（17，子进程终止时通知父进程）
18. 信号传递流程：信号产生 → 登记到未决信号集 → 进程从内核态返回用户态前检查未决信号 → 执行处理动作（默认行为、忽略、执行自定义函数）
19. signal(signum, handler) 函数作用是注册（修改）信号处理函数，返回值是上一次注册的处理函数；三种行为是 SIG_DFL 默认、SIG_IGN 忽略、自定义函数
20. 自定义信号处理下：sleep() 被信号打断会立即返回；read() 被信号打断后会自动重启
21. 处理函数组合情况：不同信号同一个函数处理；不同信号不同函数处理；相同信号同一个函数处理
22. kill 函数的本质是在进程之间传递信号，kill -9 就是 kill(pid, SIGKILL)
23. pause() 让进程挂起，直到任意一个信号被捕获处理
24. alarm(seconds) 设置闹钟，倒数结束后向进程发送 SIGALRM，返回上一次未到期闹钟的剩余秒数，传 0 取消
25. setitimer 是高级定时函数：ITIMER_REAL 走真实时间到期发 SIGALRM，ITIMER_VIRTUAL 走用户态时间到期发 SIGVTALRM，ITIMER_PROF 走用户态加内核态时间到期发 SIGPROF；支持周期性定时，比 alarm 更精确更灵活
