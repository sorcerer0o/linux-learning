# Day02 - 线程深入

## 线程的栈与数据共享

### 线程栈的隔离与"假隔离"
- 线程虽然拥有自己**独立的栈区**，但是这些栈区都来自**同一个进程的虚拟地址空间**
- 所以一个线程**理论上可以**通过地址访问到另一个线程栈帧内部的数据
- 但这会**破坏封装性**，且极易导致**内存踩踏**（越界写坏别人的栈帧），绝对不要这样做

### 悬垂指针（重点）
- 线程之间确实可以访问彼此的栈空间
- **绝对不要访问生命周期可能已经提前结束的栈空间**（如线程已退出），否则会访问到**野指针（悬垂指针）**，引发未定义行为

### 共享数据 vs 私有数据
| 线程间共享的数据 | 线程私有的数据 |
|---|---|
| 全局变量 | 栈变量（局部变量） |
| 静态变量 | 寄存器上下文 |
| 堆内存数据（通过指针传递） | 线程局部存储（`__thread` 修饰的变量） |
| 文件描述符 | |
| 信号处理器 | |

## 线程的创建与回收

- 创建线程: `pthread_create(&tid, NULL, 入口函数, 参数)`;
- **线程等待回收资源**使用函数: `pthread_join(tid, &retval)`;

### 查看线程的命令
- 查看系统所有线程的状态: `ps -eLf`
- 查看特定进程 (PID) 内线程详情: `ps -T -p <pid>`

## 线程的执行时序

- 子线程创建后与主线程形成**多个并发执行流**（多条执行通路），共同竞争 CPU 资源
- 子线程和主线程的执行顺序与父子进程一样，由**操作系统调度器决定，具有随机性**（不可预测）
- 如果想控制线程的执行时序，**不能依赖粗糙的延时函数**（如 sleep），而应该使用同步机制:
  - 互斥锁、条件变量、信号量、读写锁、屏障 (Barrier) 等

### 单核 vs 多核
- 单核 CPU 在任一时刻只能运行一个线程，多个线程仅能**交替执行**（时间片轮转）
  - 宏观上不存在真正物理层面的并行执行，微观上是串行交替的
- 多核 CPU 才支持**真正的并行**

## 线程函数错误处理（重点）

- **pthread_* 系列函数失败时并不设置全局 errno**，而是直接返回错误码（如 ESRCH、EINVAL）
- 可以通过 `strerror(返回码)` 将错误码转为可读字符串进行打印排查
```c
int ret = pthread_create(&tid, NULL, func, NULL);
if (ret != 0) {
    fprintf(stderr, "pthread_create error: %s\n", strerror(ret));
}
```

## 线程的退出

### 线程出口函数内
- 线程入口函数内部如果直接或间接调用了 `pthread_exit`，该线程会**提前终止**，后续代码不再执行（但**进程不会退出**）

### 重点区分：主线程 return 与 pthread_exit
- 主线程执行 `return 0;` 等价于调用 `exit(0)`：整个进程退出，**所有子线程被强制终止**
- 主线程调用 `pthread_exit(NULL)`：仅代表主线程自身终止，**进程不会退出**，其他子线程会继续运行直到全部结束

## 其他

- 打印指针地址使用 `printf("%p", 指针名)`;

## 练习

1. 创建两个线程，每个线程打印自己的栈变量地址，观察它们是否相邻（同一个进程的地址空间内）
2. 主线程 return 0 退出，观察子线程会不会继续打印
3. 主线程 pthread_exit(NULL)，观察子线程继续运行完毕
4. 用 ps -eLf 和 ps -T -p <pid> 观察多线程程序的线程列表
5. 子线程调用 pthread_exit 提前退出，验证线程入口函数后面的代码不执行、进程不退出
