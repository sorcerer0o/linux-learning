# Day01 - 信号

## 信号是什么

- **信号是一种异步的事件通知机制, 也是一种进程间通信机制**
- 进程收到信号后, 可以忽略 / 捕获处理 / 按默认行为处理

### 中断与信号的区别
| | 中断 | 信号 |
|---|---|---|
| 针对对象 | **CPU** | **进程** |
| 执行时机 | 产生后**立刻执行** | 产生后**可能有延迟**, 可能暂存在进程的**未决信号集**中 |
| 类型 | 硬件中断 / 软件中断 | 软件层面的事件通知 |

- 硬件中断: 硬件设备通知 CPU 需要处理事件 (如键盘输入、时钟)
- 软件中断: 软件程序通知 CPU 需要处理事件 (如系统调用)

## 信号的分类: kill -l

- `kill -l` 列出系统所有信号, 大致分两类:
  - **1-31: 标准信号 (不排队)**
    - 同一信号多次产生只会记录一次, 用**位图 (bitmap)** 存储
  - **34-64: 实时信号 (排队)**
    - 每个信号产生都会记录, 用**位图和链表**存储

### 信号执行类型
- **term**: 终止进程 (默认终止的信号类型)
- **stop**: 暂停进程
- **cont**: 继续进程
- **ign**: 忽略信号

### 常见信号
| 信号 | 值 | 产生 | 默认行为 (type) |
|---|---|---|---|
| SIGINT | 2 | Ctrl+C | term |
| SIGQUIT | 3 | Ctrl+\ | term + core dump |
| SIGKILL | 9 | kill -9 | term (不可捕获/忽略) |
| SIGTERM | 15 | kill 默认 | term (可捕获, 用于优雅退出) |
| SIGSTOP | 19 | kill -STOP / Ctrl+Z | stop (不可捕获/忽略) |
| SIGCONT | 18 | kill -CONT | cont |
| SIGCHLD | 17 | 子进程终止 | ign (父进程收信息) |

## 信号的传递流程

信号从产生到处理, 大致经过:
1. **信号的产生**: 通知进程某事件发生 (内核产生)
2. **信号的登记/挂起 (未决)**: 信号产生后进程来不及处理, 先存入进程的未决信号集
3. **信号的递达 (处理)**: 进程调度时机到来, 从内核态返回用户态之前检查未决信号, 执行对应的处理动作
4. **处理动作**: 执行默认行为 / 忽略 / 执行注册的函数 (自定义行为)

## 信号的处理方式

- 信号的三种行为:
  - **SIG_DFL**: 默认行为
  - **SIG_IGN**: 忽略
  - **自定义行为**: 注册一个处理函数 (handler)

### signal 函数 (注册/修改信号处理函数)
```c
#include <signal.h>
typedef void (*sighandler_t)(int);
sighandler_t signal(int signum, sighandler_t handler);
```
- **signal 函数的作用: 注册 (修改) 信号的处理函数**
- 参数 1 signum: 要设置处理的信号
- 参数 2 handler: 处理函数指针, 可以是函数名 / SIG_DFL / SIG_IGN
- 返回值: 返回**上一次**设置的 handler (旧的处理函数), 以便恢复

### 自定义行为的细节
- 自定义行为下, 某些系统调用会被打断:
  - `sleep()`: 当信号触发后会被**打断, 立即返回** (返回剩余秒数)
  - `read()`: 在信号触发后**会立即重启 read(), 不会立即返回** (内核 SA_RESTART 标志, 慢系统调用自动重启用)
- 处理函数执行完毕后, 程序回到被打断前的位置继续执行

### 处理函数的组合情况
- **不同信号的相同函数处理**: 一个处理函数注册给多个信号
- **不同信号的不同函数处理**: 每个信号注册各自的处理函数 (最常见)
- **相同信号的相同函数处理**: 同一函数反复注册给同一信号 (注册一次即可, 多次注册结果相同)

## kill 函数

- **kill 函数的本质是在进程之间传递信号** (发送信号给指定进程)
```c
#include <signal.h>
int kill(pid_t pid, int sig);
```
- kill(pid, SIGKILL) 就是 `kill -9 <pid>` 命令的实现原理

## 定时器和睡眠相关函数

- **pause 函数**:
```c
#include <unistd.h>
int pause(void);
```
- 进程挂起 (阻塞), 直到**任意一个信号被捕获处理** (处理完毕后返回 -1 并设置 errno=EINTR)
- 常用于让程序等待信号到来

- **alarm 函数**:
```c
#include <unistd.h>
unsigned int alarm(unsigned int seconds);
```
- 设置一个闹钟, 倒数 seconds 秒后内核向进程发送 **SIGALRM** (默认终止进程, 常配合自定义处理函数使用)
- 返回值: 上一次未到期的闹钟剩余秒数; 无则 0
- 传 0 表示取消闹钟

- **setitimer 高级定时函数**:
```c
#include <sys/time.h>
int setitimer(int which, const struct itimerval *new_value,
              struct itimerval *old_value);
```
- which 三种模式:
  - ITIMER_REAL: 真实时间 (到期发 SIGALRM)
  - ITIMER_VIRTUAL: 用户态时间 (到期发 SIGVTALRM)
  - ITIMER_PROF: 用户态+内核态时间 (到期发 SIGPROF)
- 支持周期性定时 (结构体含初值+间隔), 比 alarm 更精确更灵活
- 定时器到期发送信号, 也需要配合信号处理函数使用

## 练习

1. `kill -l` 查看系统全部信号, 数一数标准信号和实时信号各有几个
2. 用 signal 注册 SIGINT 处理函数: 按 Ctrl+C 打印 "收到 Ctrl+C" 而不退出
3. 用 signal 注册 SIGALRM, 再配合 alarm(3) 实现三秒后打印提示
4. 程序里注册 SIGINT 处理函数并调用 sleep(5), 按 Ctrl+C 观察 sleep 被打断立即返回
5. 用 setitimer ITIMER_REAL 实现每秒打印一次的周期性定时器
6. 分别给同一处理函数注册 SIGINT/SIGQUIT, 观察两个信号走同一个处理函数
7. 用 pause 挂起进程, 再用 kill 命令向它发送 SIGCONT/SIGINT 观察恢复
