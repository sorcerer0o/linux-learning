Day05 条件变量与网络协议 知识点日报

1. 虚假唤醒：线程被唤醒后发现共享条件其实并不满足，被白白唤醒一次
2. 产生虚假唤醒的三种方式：第一种 pthread_cond_broadcast 把所有等待在条件变量上的线程全部唤醒，但只有部分线程满足条件，其他不满足条件的需要继续睡眠；第二种来自内核，信号中断、内核调度策略、实现优化，操作系统不保证只有被通知的线程才返回；第三种是被信号量/条件被抢走，部分线程被唤醒后发现条件已被别的线程消费了
3. 解决虚假唤醒的方式：把判断条件的 if 改成 while 循环，被唤醒后重新检查条件，不满足就继续等待（while(条件不满足) { wait }）
4. ulimit -a 查看系统对当前用户进程的各种资源限制（文件大小、栈大小、进程数、打开文件数等）
5. lsb_release -a 查看当前 Linux 发行版的详细信息（发行商、版本号、代号）
6. 设置线程的分离属性：让子线程脱离主线程，主线程不再回收子线程，由操作系统回收子线程；分离后 pthread_join 对该线程无效
7. 查询某函数是否线程安全用 man 7 pthreads
8. 保证线程安全的方式：加锁、原子操作、无共享（不共享数据就没有竞争）
9. 函数的可重入性：可重入是指函数在执行过程中被再次调用，前后两次调用的结果是一样的（不依赖外部可变状态）
10. 保证可重入的方式：避免使用全局变量和静态变量，所有数据通过参数传递；仅调用可重入函数；避免调用非异步信号安全函数
11. 可重入函数一定是线程安全的，但线程安全不代表可重入
12. OSI 七层模型：应用层、表示层、会话层、传输层、网络层、数据链路层、物理层
13. TCP/IP 四层协议：应用层、传输层、网络层、网络接口层
14. 五层协议的体系结构：应用层、传输层、网络层、数据链路层、物理层
15. URL（统一资源定位符）是网络资源的唯一标识，能定位到具体位置；URI（统一资源标识符）范围更广，URL 是 URI 的一种
16. HTTP 响应行构成：协议版本、状态码、原因短语（对状态码的简短文本描述），如 HTTP/1.1 200 OK
17. HTTP 请求报文构成：请求行、请求头、空行、请求体；请求行由请求方法、请求资源、请求协议组成
18. 请求头携带请求的属性信息（User-Agent、Host、Content-Type 等）；空行没有实际意义，作用是把请求头与请求体分开；请求体是请求正文，存放传输的数据信息
19. HTTP 状态码分类：1xx 请求已被接受正在处理；2xx 请求资源成功；3xx 重定向；4xx 资源不存在（客户端问题）；5xx 服务器问题
