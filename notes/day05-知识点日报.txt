Day05 条件变量与网络基础 知识点日报

1. 虚假唤醒的概念：线程被唤醒后，发现共享条件其实并不满足，被白白唤醒一次
2. 产生虚假唤醒的方式：第一种是 pthread_cond_broadcast 会把所有等待在条件变量上的线程全部唤醒，但只有部分线程满足条件，其他不满足条件的线程需要继续睡眠；第二种来自内核层，信号中断、内核调度策略、实现优化都可能造成，也就是操作系统不保证只有真正被通知的线程才会返回；第三种是 signal 被抢走，部分线程被唤醒后发现条件已经被别的线程消费了
3. 解决虚假唤醒的方式：把判断条件的 if 语句改成 while 循环，被唤醒后重新检查条件，不满足就继续等待
4. ulimit -a 用于查看系统对用户进程的各种资源限制
5. lsb_release -a 用于查看当前 Linux 发行版本的详细信息
6. 设置线程属性：可以设置线程的分离属性，让子线程与主线程分离，主线程不再回收子线程，由操作系统回收子线程（pthread_detach / 分离状态）
7. 线程安全概念：查询某个函数是不是线程安全的，用 man 7 pthreads 查看手册
8. 保证线程安全的方式：加锁、原子操作、无共享（数据不共享自然就没有竞争）
9. 函数的可重入性：可重入是指函数在执行过程中被再次调用，前后两次调用的结果是一样的（不依赖外部状态）
10. 保证可重入的方式：避免使用全局变量和静态变量，所有数据通过参数传递；只调用可重入函数；避免调用非异步信号安全函数
11. 可重入函数一定是线程安全的，但线程安全不代表可重入
12. OSI 七层模型：应用层、表示层、会话层、传输层、网络层、数据链路层、物理层
13. TCP/IP 四层协议：应用层、传输层、网络层、网络接口层
14. 五层协议的体系结构：应用层、传输层、网络层、数据链路层、物理层
15. URL 是统一资源定位符，是网络资源的唯一标识
16. URI 是统一资源标识符，范围比 URL 更广，URL 是 URI 的一种
17. HTTP 响应行构成：协议版本、状态码、原因短语（对状态码的简短文本描述）
18. HTTP 请求由请求行、请求头、空行、请求体组成；请求头包含各种请求属性信息
19. 空行没有实际意义，作用就是把请求头和请求体分开
20. 请求体是请求正文，存放要传输的数据信息
21. HTTP 状态码分类：1xx 表示请求已被接受正在处理；2xx 表示请求资源成功；3xx 表示重定向；4xx 表示资源不存在（客户端问题）；5xx 表示服务器问题
