# Day05 - 条件变量与网络协议

## 虚假唤醒（重点）

- **虚假唤醒**: 线程被唤醒后，发现共享条件其实并不满足，被白白唤醒
- 产生虚假唤醒的方式（三种）:
  1. **broadcast 唤醒全部**: `pthread_cond_broadcast` 将所有等待在条件变量上的线程全部唤醒，但只有部分线程满足条件，其他不满足条件的线程需要继续睡眠
  2. **内核原因**: 信号中断、内核调度策略、实现优化（操作系统**不保证只有被通知的线程才会返回**）
  3. **signal 被抢走**: 部分线程被唤醒后，发现条件已经被别的线程消费了（条件不满足）
- **解决虚假唤醒的方式**：将判断条件的语句 `if` 改为 `while` 循环——被唤醒后重新检查条件，不满足就继续等待

```c
// 错误写法：if
if (count == 0) {
    pthread_cond_wait(&cond, &mutex);
}
// 正确写法：while
while (count == 0) {
    pthread_cond_wait(&cond, &mutex);
}
```

## 系统命令

- `ulimit -a`: 查看系统对当前用户进程的各种**资源限制**（文件大小、栈大小、进程数、打开文件数等）
- `lsb_release -a`: 查看当前 **Linux 发行版**的详细信息（发行商、版本号、代号）

## 线程属性

### 设置线程的分离属性
- 让子线程**脱离主线程**: 主线程不再回收子线程，由**操作系统**回收子线程（设置 PTHREAD_CREATE_DETACHED / 调用 pthread_detach）
- 分离后 pthread_join 对该线程无效

## 线程安全

- 查询某个函数是不是线程安全的: `man 7 pthreads`（手册中有各函数的线程安全性说明）
- 保证线程安全的方式（三种）:
  1. **加锁**（互斥锁/读写锁）
  2. **原子操作**（原子变量，不被调度打断的读写）
  3. **无共享**（不共享数据就没有竞争）

## 函数的可重入性

- **可重入**: 函数在执行过程中被再次调用（如被信号处理函数打断后再次进入），**前后两次调用的结果是相同的**（不依赖外部可变状态）
- 保证可重入的方式（三种）:
  1. 避免使用**全局变量、静态变量**，所有数据通过**参数传递**
  2. 仅调用可重入函数（避免调用不可重入的标准库函数）
  3. 避免调用**非异步信号安全函数**（在信号处理函数里尤其重要）
- **可重入函数一定是线程安全的；线程安全不代表可重入**（两者不等价）

## 网络协议分层模型

### OSI 七层模型
应用层、表示层、会话层、传输层、网络层、数据链路层、物理层
（口诀: 应表会传网数物）

### TCP/IP 四层协议
应用层、传输层、网络层、网络接口层

### 五层协议的体系结构（折中，教材常用）
应用层、传输层、网络层、数据链路层、物理层

## URL / URI

- **URL（统一资源定位符）**: 网络资源的**唯一标识**（能定位到具体资源位置，如 http://a.com/index.html）
- **URI（统一资源标识符）**: 范围更广的标识符；URL 是 URI 的一种（URL 能定位，URI 只标识）

## HTTP 报文

### 响应报文
- **响应行构成**: 协议版本、状态码、原因短语（对状态码的简短文本描述）
  - 如: `HTTP/1.1 200 OK`

### 请求报文结构
- 请求行、请求头、空行、请求体
- 请求行: 请求方法、请求资源、请求协议
- **请求头**: 携带请求的属性信息（User-Agent、Host、Content-Type 等）
- **空行**: 没有实际意义，就是为了将请求头与请求体分开
- **请求体**: 请求正文，传输的数据信息

### HTTP 状态码分类
| 码段 | 含义 |
|---|---|
| 1xx | 请求**已被接受，正在处理** |
| 2xx | 请求资源**成功**（如 200 OK） |
| 3xx | **重定向**（如 301/302） |
| 4xx | **资源不存在**（客户端错误，如 404） |
| 5xx | **服务器问题**（如 500） |
