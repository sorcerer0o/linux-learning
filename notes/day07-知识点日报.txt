Day07 TCP/UDP/网络层/网络编程 知识点日报

1. TCP 是传输层协议，特点：面向连接、可靠、面向字节流、全双工
2. TCP 首部固定 20 字节，字段：源端口（2字节）、目的端口（2字节）、序号 seq（4字节）、确认号 ack（4字节）、数据偏移（4位）、保留（6位）、标志位（6位）、窗口大小（2字节）、校验和（2字节）、紧急指针（2字节）
3. TCP 六个标志位：SYN 建立连接同步序号；ACK 确认号有效；FIN 发送方数据发完请求关闭；RST 重置连接；PSH 立即交付数据；URG 紧急指针有效
4. 三次握手：客户端发 SYN 带 seq=x；服务端回 SYN+ACK 带 seq=y 和 ack=x+1；客户端回 ACK 带 ack=y+1，连接建立
5. 为什么必须三次握手：两次握手不能保证连接正常（服务端无法确认客户端收到自己的 SYN+ACK，会浪费资源造成半开连接）；三次是保证建立连接的最少握手次数
6. 四次挥手：客户端发 FIN；服务端回 ACK（但还有数据要发）；服务端发 FIN；客户端回 ACK，连接关闭
7. 为什么是四次挥手：TCP 是全双工，每个方向要分别关闭，收到 FIN 只代表对方数据发完，本方可能还有数据要发，所以 ACK 与 FIN 分开发
8. TIME_WAIT：主动关闭方发完最后一个 ACK 后进入，等待 2MSL，目的保证最后的 ACK 能送达、让旧报文在网络中消失；大量 CLOSE_WAIT 说明服务端代码没及时 close
9. TCP 可靠传输机制：确认与超时重传、按序交付、流量控制（窗口字段）、拥塞控制（慢启动、拥塞避免、快重传、快恢复）
10. UDP 是传输层协议，特点：面向无连接、不可靠、开销小、传输速率快，面向报文保留报文边界
11. UDP 首部仅 8 字节：源端口、目的端口、长度、校验和各 2 字节
12. TCP 与 UDP 对比：TCP 面向连接可靠面向字节流首部 20 字节较慢，用于文件传输、网页、邮件；UDP 无连接不可靠面向报文首部 8 字节快，用于音视频、实时游戏、DNS
13. IP 地址用于在网络环境中确定一台主机；IPv4 是 32 位（目前主流），IPv6 是 128 位
14. IPv4 五类地址：A 类 1-126.x.x.x 大型网络；B 类 128.0-191.255 中型网络；C 类 192.0.0-223.255.255 小型网络；D 类 224-239 组播；E 类 240-255 保留实验；127.x.x.x 是回环地址
15. IP 协议头 20 字节，关键字段：版本（4位）、首部长度（4位）、总长度（2字节）、TTL 生存时间（1字节，每跳减1防环路）、协议（1字节，TCP=6、UDP=17）、首部校验和（2字节）、源IP（4字节）、目的IP（4字节）
16. 子网掩码用于划分网络号和主机号：掩码中 1 对应网络号 0 对应主机号，网络号等于 IP 与掩码按位与；主机位全 0 是网络地址全 1 是广播地址；可容纳主机数等于 2 的主机位数次方减 2
17. 路由转发：路由器根据目的 IP 查路由表决定转发到哪个网络，同网段直接到达，跨网段必须经过路由器（默认网关），每经过一个路由器 TTL 减 1
18. NAT（网络地址转换）：可以将私网 IP 转换为公网 IP，也可以将公网 IP 转换为私网 IP；私网地址段：10.x、172.16-31.x、192.168.x；作用是多台私网主机共享公网 IP 上网缓解 IPv4 枯竭
19. socket 抽象层：网络数据在内核层的收发由内核协议栈负责不需要程序员管理，程序员通过 socket 文件描述符与内核协议栈交互
20. 大端：低地址存高位高地址存低位；小端：低地址存低位高地址存高位；本机字节序 x86 是小端，网络字节序统一是大端，发送前本机序转网络序接收后转回
21. 大小端转换函数：htonl 32位本机序转网络序、htons 16位本机序转网络序、ntohl 32位网络序转本机序、ntohs 16位网络序转本机序；端口 16 位用 htons/ntohs，IP 地址 32 位用 htonl/ntohl
22. IP 地址转换函数：inet_aton 和 inet_addr 把点分十进制字符串转网络字节序二进制 IP；inet_ntoa 把网络字节序转回点分十进制字符串；struct in_addr 中 s_addr 类型是 uint32_t 无符号整数；inet_ntoa 返回静态缓冲区不可重入
23. TCP 编程流程：服务端 socket→bind→listen→accept→send/recv→close；客户端 socket→connect（触发三次握手）→send/recv→close；accept 一个连接返回一个新文件描述符
24. UDP 编程流程：无需 connect/listen/accept，直接 sendto/recvfrom 收发，天然无连接
