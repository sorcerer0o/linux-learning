Day03 线程取消、互斥锁与HTTP 知识点日报

1. 取消点：线程被取消时实际发生终止的位置（要执行到取消点函数才会真正被取消）；具备取消点的函数特征是（1）几乎所有的阻塞函数都具备取消点，（2）具备 IO 操作功能的函数具备取消点；使用 man 7 pthreads 查询
2. 手动创建取消点使用 pthread_testcancel()，在代码关键位置主动检查取消标记
3. 线程取消的五个步骤：第一步调用 pthread_cancel 传入目标线程 id，系统将目标线程的内部取消标记设置为真；第二步被取消线程执行到取消点函数时检查标志位；第三步取消点函数检测到取消状态后，在终止线程之前执行清理函数（pthread_cleanup_push 注册的，用于释放占用资源、解锁互斥锁）；第四步完成数据清理后线程执行退出操作，操作系统或线程库负责销毁 thread local 数据；第五步 pthread_join 返回，接受线程取消状态 PTHREAD_CANCELED
4. 被取消后的返回值为宏 PTHREAD_CANCELED，即 ((void *)-1)
5. pthread_cleanup_push 和 pthread_cleanup_pop 要在同一作用域下成对出现；pop 的 execute 参数为 0 不执行清理函数，非 0 执行
6. 当线程因为在 start_routine 入口函数中 return 结束进程时，清理函数栈不会弹栈（清理函数不执行）
7. 互斥锁用于保证任意时刻只有一个线程能够访问共享资源；使用模式：加锁、访问修改共享资源、解锁；解锁必须覆盖所有退出路径否则死锁
8. 死锁的三种情况：重复上锁（上锁后未解锁再上锁）；持锁线程未释放锁提前终止，其他线程获取锁；线程1拥有锁1想获取锁2、线程2拥有锁2想获取锁1，互相争抢造成死锁（环型等待）
9. pthread_mutex_trylock 获取锁失败返回错误值不会阻塞，可做非阻塞加锁
10. 读写锁：读共享写排他，多个线程可同时读，写线程独占，适合读多写少场景
11. 条件变量的原理：线程在共享资源不满足某个条件时挂起，直到另一个线程唤醒它；配合互斥锁使用，wait 会释放锁并挂起
12. HTTP 请求报文中包括请求行、请求头、空行、请求体四部分
13. 请求行构成：请求方法（GET/POST 等）、请求资源（URL）、请求协议（HTTP 版本），如 GET /index.html HTTP/1.1
14. 请求头携带请求属性信息（User-Agent、Host、Content-Type 等）；空行没有实际意义，作用是把请求头与请求体分开；请求体是请求正文，存放传输的数据信息
