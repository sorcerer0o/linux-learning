# Day07 - 计算机网络 (TCP/UDP/网络层/网络编程)

## 一、TCP 协议 (传输层, 面试常考)

### 1、基本概念
- TCP 是**传输层**协议
- 特点: **面向连接**、**可靠**、**面向字节流**、**全双工**
  - 面向连接: 通信前必须先建立连接, 通信完释放连接
  - 可靠: 确认、重传、按序交付、流量控制、拥塞控制
  - 面向字节流: 数据看作无结构的字节流, 不保留报文边界
  - 全双工: 通信双方可同时收发

### 2、TCP 首部 (固定 20 字节, 选项最多可到 60 字节)
| 字段 | 大小 | 作用 |
|---|---|---|
| 源端口 | 2 字节 | 发送方进程的端口 |
| 目的端口 | 2 字节 | 接收方进程的端口 |
| 序号 seq | 4 字节 | 本报文段数据的第一个字节在整个字节流中的编号 |
| 确认号 ack | 4 字节 | 期望收到对方下一个字节的序号, 也说明该序号之前全部收到 |
| 数据偏移 | 4 位 | TCP 首部的长度 (以 4 字节为单位, 最大 15*4=60) |
| 保留 | 6 位 | 保留未用, 置 0 |
| 标志位 | 6 位 | URG / ACK / PSH / RST / SYN / FIN |
| 窗口大小 | 2 字节 | 接收方允许发送方发送的窗口大小 (流量控制) |
| 校验和 | 2 字节 | 覆盖首部+数据的校验和 (强校验) |
| 紧急指针 | 2 字节 | 紧急数据的位置 (配合 URG) |

#### 六个标志位 (重点)
- **SYN** (Synchronize): 建立连接时用于同步序号
- **ACK** (Acknowledge): 确认号字段有效
- **FIN** (Finish): 发送方数据已发完, 请求关闭连接
- **RST** (Reset): 连接异常, 强制重置
- **PSH** (Push): 立即交付, 不等缓冲区满
- **URG** (Urgent): 紧急指针有效, 紧急数据优先处理

### 3、三次握手 (建立连接, 重点)
```
Client                          Server
  |---- SYN=1, seq=x ----------->|  ① 客户端: 请求建立连接
  |<-- SYN=1, ACK=1, seq=y, ack=x+1 --|  ② 服务端: 确认并同步
  |---- ACK=1, seq=x+1, ack=y+1 -->|  ③ 客户端: 确认, 连接建立
```
- 第一次: 客户端发 SYN, 携带初始序号 seq=x (服务器收到: 客户端的发送能力正常)
- 第二次: 服务端回 SYN+ACK, 携带自己的序号 seq=y, 并确认 ack=x+1 (客户端收到: 服务端收发能力正常)
- 第三次: 客户端回 ACK, ack=y+1 (服务端收到: 客户端的接收能力正常)
- **为什么必须是三次**:
  - 两次握手不能保证连接正常: 服务端无法确认客户端是否收到自己的 SYN+ACK (若客户端没收到, 会重复发 SYN, 造成服务端资源浪费/半开连接)
  - 四次可以, 但三次已是**保证建立连接的最少握手次数** (第三次的 ACK 还可以捎带数据)

### 4、四次挥手 (释放连接, 重点)
```
Client                          Server
  |---- FIN=1, seq=u ----------->|  ① 客户端: 数据发完, 关闭我的方向
  |<-- ACK=1, ack=u+1 -----------|  ② 服务端: 确认 (服务端还能继续发数据)
  |<-- FIN=1, seq=w -------------|  ③ 服务端: 数据也发完, 关闭
  |---- ACK=1, ack=w+1 --------->|  ④ 客户端: 确认关闭
```
- 为什么是四次: TCP 是**全双工**, 每个方向的关闭都要单独完成; 收到 FIN 只代表对方数据发完, 本方可能还有数据要发, 所以 ACK 与 FIN 不能合并
- **TIME_WAIT (2MSL 等待)**: 主动关闭方发送最后一个 ACK 后进入, 等待 2 倍报文最大生存时间
  - 目的 1: 保证最后的 ACK 能送达 (若丢失可重发)
  - 目的 2: 让本连接的所有旧报文在网络中消失, 避免影响新连接
- 常见问题: 大量 TIME_WAIT 会占用端口, 高并发服务端需要处理 (如调优 keepalive、端口复用)

### 5、状态迁移 (重点状态)
- 服务端: LISTEN(监听) → SYN_RCVD(收到SYN) → ESTABLISHED(已连接) → CLOSE_WAIT(等待关闭) → LAST_ACK(最后确认) → CLOSED
- 客户端: SYN_SENT(已发SYN) → ESTABLISHED → FIN_WAIT_1 → FIN_WAIT_2 → TIME_WAIT → CLOSED
- 观察命令: `netstat -tunap` 或 `ss -tunap` (如看到大量 CLOSE_WAIT 说明服务端代码没及时 close)

### 6、TCP 的可靠传输机制 (理解)
- **确认与重传**: 收到数据回 ACK; 超时未确认则重传
- **按序交付**: 序号保证数据按序重组, 乱序先缓存
- **流量控制**: 接收方通过窗口字段限制发送速率, 防止接收方处理不过来
- **拥塞控制**: 慢启动、拥塞避免、快重传、快恢复 (防止网络过载)

## 二、UDP 协议 (传输层)

### 1、基本概念
- 也是**传输层**协议
- 特点: **面向无连接**、**不可靠**、**开销小**、**传输速率快**
- 面向报文: 保留报文边界, 一次收发一个完整报文 (不拆分不合并)

### 2、UDP 首部 (仅 8 字节)
| 字段 | 大小 | 作用 |
|---|---|---|
| 源端口 | 2 字节 | 发送方端口 |
| 目的端口 | 2 字节 | 接收方端口 |
| 长度 | 2 字节 | UDP 报文总长度 (首部+数据) |
| 校验和 | 2 字节 | 校验首部和数据 |

- 无序号、无确认、无重传、无连接状态 → 快, 但可能丢包、乱序、重复

### 3、TCP vs UDP 对比
| | TCP | UDP |
|---|---|---|
| 连接 | 面向连接 (三次握手) | 无连接 |
| 可靠性 | 可靠 (确认/重传/排序) | 不可靠 |
| 传输方式 | 面向字节流 | 面向报文 |
| 全双工 | 是 | 是 |
| 首部大小 | 20 字节 | 8 字节 |
| 速率/开销 | 慢、开销大 | 快、开销小 |
| 应用场景 | 文件传输(FTP)、网页(HTTP)、邮件(SMTP) | 音视频、实时游戏、DNS、广播 |

## 三、网络层

### 1、IP 地址
- 在网络环境中确定一台主机, 需要知道 IP 地址
- **IPv4**: 32 位, 目前主流
- **IPv6**: 128 位, 解决 IPv4 地址枯竭

### 2、IPv4 的五类地址
| 类别 | 范围 | 用途 | 特点 |
|---|---|---|---|
| A 类 | 1.x.x.x ~ 126.x.x.x | 大型网络 | 网络号占 1 字节, 主机多 |
| B 类 | 128.0.x.x ~ 191.255.x.x | 中型网络 | 网络号占 2 字节 |
| C 类 | 192.0.0.x ~ 223.255.255.x | 小型网络 | 网络号占 3 字节, 主机少 |
| D 类 | 224.x.x.x ~ 239.x.x.x | 组播 (多播) | 不分网络号主机号 |
| E 类 | 240.x.x.x ~ 255.x.x.x | 保留实验 | 不用 |

- 注意: **127.x.x.x 是回环地址** (本机测试, 如 127.0.0.1/localhost); A 类从 1 开始, 0.x 保留

### 3、IP 协议头 (20 字节)
| 字段 | 大小 | 作用 |
|---|---|---|
| 版本 | 4 位 | IPv4 / IPv6 (v4 为 0100) |
| 首部长度 | 4 位 | IP 首部长度 (以 4 字节为单位, 最小 5) |
| 服务类型 | 1 字节 | 优先级、延迟、吞吐量等 QoS 信息 |
| 总长度 | 2 字节 | IP 报文总长度 (首部+数据, 最大 65535) |
| 标识 | 2 字节 | 分片时同一报文各片的标识 (可拼接) |
| 标志 | 3 位 | DF 不分片 / MF 还有分片 |
| 片偏移 | 13 位 | 分片在原报文中的偏移位置 |
| 生存时间 TTL | 1 字节 | 每经过一个路由器减 1, 为 0 丢弃 (防止环路) |
| 协议 | 1 字节 | 上层协议 (TCP=6、UDP=17、ICMP=1) |
| 首部校验和 | 2 字节 | 只校验 IP 首部 (每跳都要重新计算) |
| 源 IP 地址 | 4 字节 | 发送方 IP |
| 目的 IP 地址 | 4 字节 | 接收方 IP |

### 4、子网掩码
- 用于划分**网络号**和**主机号**: 掩码中连续的 1 对应网络号, 0 对应主机号
- 例: 192.168.1.100 掩码 255.255.255.0 → 网络号 192.168.1.0, 主机号 100
- 计算规则:
  - 网络号 = IP 与掩码按位与
  - 主机号 = IP 与掩码取反后按位与
- 主机位全 0 → 网络地址 (不能分配给主机); 全 1 → 广播地址
- 可容纳主机数 = 2^主机位数 - 2

### 4、路由转发
- 路由器根据**目的 IP 地址**查**路由表**, 决定数据包转发到哪个网络/下一跳
- 同网段: 直接通过交换机/二层到达 (不需要路由器)
- 跨网段: 必须经过路由器 (默认网关)
- 每经过一个路由器: TTL 减 1, 减到 0 丢弃并回报 ICMP

### 5、NAT (网络地址转换)
- **NAT 可以将私网 IP 转换为公网 IP, 也可以将公网 IP 转换为私网 IP**
- 私网地址 (RFC1918): 10.0.0.0/8、172.16.0.0~172.31.255.255、192.168.0.0/16
- 作用: 多个私网主机共享少量公网 IP 访问互联网; 缓解 IPv4 地址枯竭, 同时隐藏内网结构
- 典型: 家用路由器默认开启 NAT

## 四、网络编程

### 1、原理
- 数据在网络内核层的收发由**内核协议栈**负责, 不需要程序员管理
- 程序员通过 **socket (套接字) 抽象层**与内核协议栈交互
- socket 本质是一个文件描述符, 用 open/close 类似的接口操作网络

### 2、大小端 (重点, 面试常考)
- **大端 (Big Endian)**: 低地址存高位, 高地址存低位
- **小端 (Little Endian)**: 低地址存低位, 高地址存高位 (记忆: 小端 = 低低, 低地址存低字节)
- **本机字节序**: 数据在内存中存储的字节序, x86 平台是**小端**
- **网络字节序**: 数据在网络上传输的字节序, 统一使用**大端**
- 编程中: 发送前 本机序 → 网络序; 接收后 网络序 → 本机序
- 验证方法: 存储 0x12345678, 看内存第一个字节是 0x12(大端) 还是 0x78(小端)

### 3、大小端转换函数
```c
#include <arpa/inet.h>
// h = host 本机   n = network 网络   l = long(32位)   s = short(16位)
uint32_t htonl(uint32_t hostlong);   // 32位: 本机序 -> 网络序 (IP 地址)
uint16_t htons(uint16_t hostshort);  // 16位: 本机序 -> 网络序 (端口)
uint32_t ntohl(uint32_t netlong);    // 32位: 网络序 -> 本机序
uint16_t ntohs(uint16_t netshort);   // 16位: 网络序 -> 本机序
```
- 典型应用: 端口号 16 位用 htons/ntohs; IP 地址 32 位用 htonl/ntohl

### 4、IP 地址转换函数
```c
struct in_addr {
    in_addr_t s_addr;   // in_addr_t -> uint32_t -> 无符号 int
};

// 点分十进制字符串(如"192.168.1.1") -> 网络字节序二进制 IP
int inet_aton(const char *cp, struct in_addr *inp);
in_addr_t inet_addr(const char *cp);

// 网络字节序二进制 IP -> 点分十进制字符串
char *inet_ntoa(struct in_addr in);
```
- 应用: 用户输入字符串 IP → 转网络序填入 sockaddr_in; 收到对端地址 → 转回字符串打印
- 注意: inet_ntoa 返回静态缓冲区, 不可重入 (多线程需加锁或用 inet_ntop)
- 验证大小端: 转换前后打印数值即可印证本机小端、网络大端

### 5、socket 编程基础 (下一节重点, 先看流程)
```
TCP 服务端:                    TCP 客户端:
socket() -> 创建套接字          socket() -> 创建套接字
bind()   -> 绑定地址端口        connect() -> 发起连接 (触发三次握手)
listen() -> 监听                |-- 连接建立后 --|
accept() -> 接受连接 (返回新fd)   send()/recv() -> 收发数据
send()/recv() -> 收发数据        close() -> 关闭
close() -> 关闭
```
- 一个服务端 accept 一个连接返回一个**新文件描述符** (用于该连接), 监听 fd 继续 accept
- UDP 则无需 connect/listen/accept: 直接 sendto/recvfrom 收发, 天然无连接
