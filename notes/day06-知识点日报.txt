Day06 复习与线程局部存储 知识点日报

1. 解决虚假唤醒的方法：把判断条件的 if 改成 while 循环，被唤醒后重新检查条件，不满足就继续等待
2. 产生虚假唤醒的原因：broadcast 唤醒全部但只有部分满足条件；内核信号中断、调度策略、实现优化（不保证只有被通知的线程返回）；signal 被其他线程抢走，条件已被消费
3. pthread_cond_timedwait 相对于 pthread_cond_wait 的特点：既可以被 signal/broadcast 唤醒，也可以因为设置的 abstime 绝对时间到达而超时返回；被唤醒返回 0，超时返回错误码 ETIMEDOUT；abstime 是绝对时间
4. OSI 七层模型：应用层、表示层、会话层、传输层、网络层、数据链路层、物理层
5. TCP/IP 四层协议：应用层、传输层、网络层、网络接口层
6. 五层协议体系结构：应用层、传输层、网络层、数据链路层、物理层
7. HTTP 请求报文四部分：请求行（请求方法 GET/POST、资源路径 URL、协议与版本 HTTP/1.1）、请求头（key-value 键值对，User-Agent、Host、Content-Type 等）、空行（分隔请求头与请求正文）、请求体（请求正文，POST 提交的数据）
8. GET 主要用来查询数据，数据附着在地址栏；POST 主要用来提交数据，数据放在请求体中不上地址栏
9. HTTP 响应报文四部分：响应行（协议与版本、状态码、原因短语）、响应头（附加信息，Set-Cookie、Content-Type、Content-Length 等）、空行、响应体（响应正文，文本或二进制）
10. HTTP 状态码：1xx 正在处理；2xx 正常；3xx 重定向；4xx 资源不存在（服务器正常）；5xx 服务器异常
11. http 是未加密的明文传输，内容易被窃听不安全，但传输效率高；https 是加密传输更安全
12. 线程局部存储变量用 __thread 关键字修饰，在全局变量的位置定义，但每个线程中独一份（各线程持有的地址不同），互不影响
13. __thread 只能修饰全局变量或静态变量，不能修饰局部变量、函数参数、函数返回值；只能修饰简单类型
14. TLS 变量底层存储在进程的 TLS 段中，每个线程的 TCB 中保存 TLS 指针指向自己的副本区域，访问时通过 TLS 指针加偏移定位自己的副本，本质是用空间换时间
15. TLS 的函数接口：pthread_key_create（创建键，可传 destructor 在线程退出时自动释放资源）、pthread_setspecific（存本线程的值）、pthread_getspecific（取本线程的值）、pthread_key_delete（删除键）
16. __thread 是编译期静态分配简单高效；pthread_key 系列是运行期动态分配更灵活
17. 现代 C 库的 errno 就是线程局部存储实现，所以多线程下 errno 是线程安全的
